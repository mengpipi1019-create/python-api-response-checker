# AI 协作记录

创建日期：2026-09-15。项目类型：个人测试开发练习 / AI 辅助 Demo。

## 背景

为准备测试开发方向求职，希望制作一个不重复已有模型部署项目、容易运行和解释的小作品。选择模拟商品接口返回数据校验，不接触真实业务接口或个人数据。

## 问题与方案

接口响应中的字段缺失、类型混用和业务非法值，是本次练习要处理的问题场景，不是声称在企业实际发现过的缺陷。用 Python 将规则拆成结构、必填、类型和值检查，集中收集错误，输出字段路径和错误原因。

值得解释的边界：Python 中 `bool` 是 `int` 的子类，若只使用 `isinstance(value, int)`，可能让 `true` 通过库存整数检查。因此用精确类型判断，并加入测试。这个例子是设计时考虑的边界，不虚构“线上排障”的经历。

## 协作分工

- 用户：提出新项目需求、求职用途，选择 GitHub 作为发布位置。
- AI 助手：提出具体 Demo 方案，生成代码、模拟数据和测试，在本地执行验证并整理说明。
- 尚未确认：用户本人是否已经独立运行、逐行理解、修改规则和复现测试。仓库完成不自动代表个人熟练度达标。

运行时使用 Python 标准库，不调用模型 API；“AI 协作”指开发过程，不意味着这是一个内置 AI 的产品。

## 当前结果

可运行的命令行工具、正常/异常样例、30 项自动化测试、JSON 错误报告。异常样例定位 6 处预先设置的问题；结果仅适用于本 Demo 的规则与测试范围。

## 申请表简述（如实表述当前阶段）

为练习测试开发，我在 AI 辅助下搭建了一个 Python 接口返回数据检查器，使用模拟商品数据处理缺字段、类型错误、负数价格和重复编号等问题。我提出项目需求，由 AI 辅助拆解规则、编写代码和测试，工具会输出具体错误位置及 JSON 报告。本地运行的 30 项测试均通过，异常样例中的 6 处预设问题均被定位。目前已形成可运行 Demo，正在补充独立复现与代码理解。

## 使用前的个人验收

1. 自己运行正常和异常样例，说清退出码 0、1、2。
2. 解释为什么 `true` 不能当成库存整数。
3. 自己修改一个校验规则，并先补一个会失败的测试，再实现修改。

完成后才更新个人能力描述；不提前写“独立开发”“实习交付”“线上发现缺陷”或效率提升百分比。
